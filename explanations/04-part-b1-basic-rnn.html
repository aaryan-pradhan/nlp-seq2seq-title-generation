Part B1

The basic RNN Seq2Seq model

The encoder–decoder from page 2, built with GRUs, trained on the cleaned articles, and scored with ROUGE. Every later model is compared against this one.

Useseverything on page 2: embeddings, masks, softmax and cross-entropy, GRUs, bidirectional reading, the encoder–decoder, teacher forcing, greedy decoding. Also Adam, epochs, dropout and gradient clipping from page 1, and the cleaned data from Part A.
assignment_spec.pdf · B1
"EncoderRNN takes an input token sequence as input, and maps them into some vector embeddings which are then fed to a bidirectional Gated Recurrent Unit (GRU) capturing the meaning of the entire sequence into some hidden embeddings. DecoderRNN takes as input one token as input along with the previous hidden state, encodes the token into vector embedding and processes it through a GRU (uni-directional) to get the current hidden state and outputs. These outputs are fed through a linear Feed Forward Network (FFN) to map it to the vocabulary dimension, obtaining a set of logits. Perform softmax on the logits and return this probability distribution of tokens along with the current hidden state. […] Note that during training, however, the input token fed to the DecoderRNN is the actual target token in the ground truth, and not the token generated in the previous time step. This process is also known as teacher-forcing."

Each phrase maps directly onto page 2. "Vector embeddings" is section 3, the "bidirectional GRU" is sections 9–10, "logits" and "softmax" are section 5, the encoder feeding the decoder is section 11, and teacher forcing is section 12. B1 adds no new concepts. It fixes concrete sizes and wires the pieces together.

1. Building the vocabulary

assignment_spec.pdf · B1, task 1
"While creating the vocabulary, consider only tokens that appear in at least 1% of the training set. You can use a hidden dimension of 300."

The code counts, for every cleaned word, how many different training articles it appears in (its document frequency), and keeps the words that clear 1%:

\[ \text{keep } w \iff \frac{\#\{\text{articles containing } w\}}{N} \ge 0.01, \qquad N = 13{,}379 \;\Rightarrow\; w \text{ must appear in at least } 134 \text{ articles} \]

\(0.01 \times 13{,}379 = 133.79\), and a count has to be a whole number, so at least 134. That leaves 9,211 words, plus the four special tokens, for \(V = 9{,}215\).

Why a threshold at all? The embedding table and the decoder's output layer each have one row per vocabulary word (see the parameter count below). A word seen in only a handful of articles would add a full row of parameters while providing almost no examples to learn it from.

In the notebook · the vocabulary comes from article text only

create_vocabulary(paragraphs, titles, …) accepts the titles but only counts words in paragraphs. A title word that's rare in article bodies, which describes many names, becomes <UNK> (ID 3) in the training targets. tokenize_text also doesn't add <SOS> or <EOS>, so the title "great barrier reef" becomes just the three word IDs.

2. The model, with every size filled in

Encoder (EncoderRNN)

\[ \begin{aligned} \mathbf{e}_i &= \operatorname{Dropout}_{0.3}\big(E_{\text{enc}}[x_i]\big) \in \mathbb{R}^{300} && i = 1, \ldots, L \\ \overrightarrow{\mathbf{h}}_i,\ \overleftarrow{\mathbf{h}}_i &= \text{bidirectional GRU over } \mathbf{e}_1, \ldots, \mathbf{e}_L && \text{each} \in \mathbb{R}^{300} \\ \mathbf{c} &= [\overrightarrow{\mathbf{h}}_L ; \overleftarrow{\mathbf{h}}_1] \in \mathbb{R}^{600} && \text{both directions' final states} \end{aligned} \]

Bridge (hidden_projection)

\[ \mathbf{s}_0 = W_p\,\mathbf{c} + \mathbf{b}_p, \qquad W_p \in \mathbb{R}^{300 \times 600} \]

The encoder's summary has 600 numbers (two directions of 300) but the decoder GRU's state has 300, so a linear layer (page 1, section 2) maps one to the other. This is \(f(\mathbf{c})\) from page 2, section 11.

Decoder (DecoderRNN), one step

\[ \begin{aligned} \mathbf{u}_t &= \operatorname{ReLU}\big(E_{\text{dec}}[y_{t-1}]\big) \in \mathbb{R}^{300} \\ \mathbf{s}_t &= \mathrm{GRU}_{\text{dec}}(\mathbf{u}_t, \mathbf{s}_{t-1}) \in \mathbb{R}^{300} \\ \mathbf{o}_t &= W_o\,\mathbf{s}_t + \mathbf{b}_o \in \mathbb{R}^{9215} \end{aligned} \]

The decoder has its own embedding table \(E_{\text{dec}}\), separate from the encoder's. The ReLU after it follows the spec's "add dropout/ReLU where you see fit". The decoder returns the logits \(\mathbf{o}_t\). Softmax is applied inside the loss (page 2, section 6), so the LogSoftmax layer defined in the class is never actually called.

docs/report.pdf · bugs hit and fixed
  • Manual .to(device) calls caused shape mismatches and GPU memory overflows. They were removed in favour of letting Accelerate place every tensor.
  • Variable-length sequences broke the loss computation. This was fixed with a collate_fn that pads every batch, plus ignore_index=PAD_TOKEN so padding never counts.
  • Index errors occurred when the target length and decoder output length disagreed. The target sequence is now sliced or padded to match.

3. One training step, in order

  1. Batch. Take 8 (article, title) pairs and pad each group to its longest member.
  2. Encode. Run the encoder and projection to get \(\mathbf{s}_0\).
  3. Decode with teacher forcing. For \(t = 1, \ldots, T\), feed \(y_{t-1}\) (with \(y_0 = \langle\mathrm{SOS}\rangle\)) and record the logits \(\mathbf{o}_t\).
  4. Loss. Compute the masked cross-entropy from page 2, section 6 over all \(8T\) positions, skipping <PAD>.
  5. Backward. accelerator.backward(loss) computes all gradients by backpropagation, including through every decoder and encoder time step.
  6. Clip. Rescale the gradient if its length exceeds 1.0.
  7. Update. One Adam step with learning rate 0.001.

No position ever has <EOS> as its target, because the tokenized titles don't contain one. By page 2, section 13, the model therefore can't learn to stop.

Mixed precision (fp16) via Accelerate

Numbers are normally stored in 32 bits. Accelerator(mixed_precision="fp16") runs most matrix multiplications in 16-bit floats instead, which roughly halves their memory and uses faster GPU routines. The parameters themselves stay in 32 bits. The catch is range: 16-bit floats can't exceed 65,504, and gradients smaller than roughly \(6\times10^{-8}\) round to exactly zero. Loss scaling prevents that:

\[ \nabla_\theta (S \cdot \mathcal{L}) = S \cdot \nabla_\theta \mathcal{L} \quad\Rightarrow\quad \text{backpropagate } S\mathcal{L}, \text{ then use } \frac{1}{S}\nabla_\theta(S\mathcal{L}) \text{ for the update} \]

Multiplying the loss by a large factor \(S\) multiplies every gradient by \(S\) (differentiation is linear), which lifts tiny gradients back above the rounding threshold during backpropagation. They're divided by \(S\) again before the Adam step, so the update is unchanged. If a scaled gradient overflows, the step is skipped and \(S\) is reduced. The report measured about a 20% reduction in training time from mixed precision.

4. Generating titles for the test set

At evaluation time there's no target, so the model decodes greedily (page 2, section 13) for up to MAX_NEW_TOKENS = 10 steps, feeding each prediction back in. The loop exits early only if every article in the batch produces <EOS> on the same step. The predicted IDs are turned back into words by decode_outputs, which stops at the first <EOS>, drops <SOS> and <PAD>, and writes out-of-vocabulary IDs as the string <UNK>.

The reference titles go through the same path: cleaned title, then vocabulary IDs, then words. So a reference word outside the vocabulary also appears as <UNK>.

5. Scoring: how ROUGE works

assignment_spec.pdf · B1, task 3
"Use the trained model to generate titles for articles in the test set, and calculate the ROUGE-1, ROUGE-2 and ROUGE-L f1 scores."

ROUGE measures how much a generated title overlaps with the reference title. The project uses the rouge_score library with use_stemmer=True. Both titles are first lowercased, every character that isn't a letter or digit becomes a space (so <UNK> becomes the word "unk"), and words are reduced by the Porter stemmer.

ROUGE-N: overlapping n-grams

An n-gram is a run of \(n\) consecutive words: unigrams for \(n = 1\), bigrams for \(n = 2\). Overlap counts are clipped, so a word the generator repeats can't match more times than it appears in the reference:

\[ \mathrm{match}(g) = \min\big(\mathrm{count}_{\text{gen}}(g),\ \mathrm{count}_{\text{ref}}(g)\big) \] \[ P_N = \frac{\sum_{g} \mathrm{match}(g)}{\sum_{g} \mathrm{count}_{\text{gen}}(g)}, \qquad R_N = \frac{\sum_{g} \mathrm{match}(g)}{\sum_{g} \mathrm{count}_{\text{ref}}(g)}, \qquad F = \frac{2 P R}{P + R} \]

The sums run over every distinct n-gram \(g\). Precision \(P\) asks what fraction of what was generated is right. Recall \(R\) asks what fraction of the reference was recovered. \(F\), their harmonic mean (0 when both are 0), is high only when both are. Generating many words raises recall but lowers precision, and generating one safe word does the opposite.

ROUGE-L: longest common subsequence

A subsequence keeps words in order but may skip some. ROUGE-L uses the length of the longest one the two titles share:

\[ P_L = \frac{\mathrm{LCS}(\text{gen}, \text{ref})}{|\text{gen}|}, \qquad R_L = \frac{\mathrm{LCS}(\text{gen}, \text{ref})}{|\text{ref}|}, \qquad F_L = \frac{2 P_L R_L}{P_L + R_L} \] \[ \mathrm{LCS}(i, j) = \begin{cases} 0 & i = 0 \text{ or } j = 0 \\ \mathrm{LCS}(i-1, j-1) + 1 & \text{gen}_i = \text{ref}_j \\ \max\big(\mathrm{LCS}(i-1, j),\ \mathrm{LCS}(i, j-1)\big) & \text{otherwise} \end{cases} \]

\(|\cdot|\) is length in words. \(\mathrm{LCS}(i, j)\) is the answer for the first \(i\) generated words and the first \(j\) reference words, filled in as a table, and the full answer is the bottom-right cell. Unlike ROUGE-2, ROUGE-L rewards words in the right order even when other words sit between them.

Worked example 1

Reference: "great barrier reef" (3 words) · Generated: "barrier reef coral reef" (4 words)

\[ \text{ROUGE-1: } \mathrm{match} = \underbrace{1}_{\text{barrier}} + \underbrace{\min(2, 1)}_{\text{reef}} = 2, \quad P = \tfrac{2}{4},\ R = \tfrac{2}{3},\ F = \frac{2 \cdot 0.5 \cdot 0.667}{0.5 + 0.667} = 0.571 \] \[ \text{ROUGE-2: gen bigrams } \{\text{barrier reef, reef coral, coral reef}\},\ \text{ref } \{\text{great barrier, barrier reef}\} \Rightarrow P = \tfrac13,\ R = \tfrac12,\ F = 0.400 \] \[ \text{ROUGE-L: } \mathrm{LCS} = |\text{barrier reef}| = 2 \Rightarrow P = \tfrac24,\ R = \tfrac23,\ F = 0.571 \]
Worked example 2 · when ROUGE-1 and ROUGE-L disagree

Reference: "barrier reef" · Generated: "reef barrier"

\[ \text{ROUGE-1: } F = 1.0 \qquad \text{ROUGE-2: } F = 0 \qquad \text{ROUGE-L: } \mathrm{LCS} = 1 \Rightarrow F = 0.5 \]

ROUGE-1 ignores order entirely, and ROUGE-L penalizes the swap. When a generated title's matching words already appear in the reference's order, as in example 1, LCS equals the unigram match count and the two scores coincide. That's common for short titles, which is why many rows in this project report identical ROUGE-1 and ROUGE-L.

The reported number is the mean over the 100 test articles:

\[ \overline{F} = \frac{1}{100}\sum_{k=1}^{100} F^{(k)} \]

One consequence is used on the results page: a single article moving from \(F = 0\) to \(F = 1\) shifts the mean by exactly \(0.01\).

The extra word-level F1

The B1 evaluation also treats each title as an unordered set of words \(G_k\) (generated) and \(R_k\) (reference), and pools the counts over all 100 articles before dividing:

\[ \mathrm{TP} = \sum_k |G_k \cap R_k|, \quad \mathrm{FP} = \sum_k |G_k \setminus R_k|, \quad \mathrm{FN} = \sum_k |R_k \setminus G_k| \] \[ P = \frac{\mathrm{TP}}{\mathrm{TP} + \mathrm{FP}}, \qquad R = \frac{\mathrm{TP}}{\mathrm{TP} + \mathrm{FN}}, \qquad F_1 = \frac{2PR}{P+R} \]

\(\cap\) is "in both", and \(G \setminus R\) is "in \(G\) but not in \(R\)". TP, FP and FN are true positives, false positives and false negatives. Pooling counts first is called micro-averaging.

7. Why the score is this low: four causes

Cause 1 · it always writes about ten words

With no <EOS> in any training target, the model essentially never predicts it, so generation runs to the 10-token cap while cleaned reference titles are usually just a few words. Even a perfect hit is capped. Suppose a reference has \(r\) words and all of them appear among 10 generated words:

\[ P = \frac{r}{10},\quad R = 1 \;\Rightarrow\; F = \frac{2 \cdot \frac{r}{10} \cdot 1}{\frac{r}{10} + 1} = \frac{2r}{r + 10} \qquad r = 3:\ F = \tfrac{6}{13} \approx 0.46 \]

That's the best case. The word-level numbers show exactly this signature: recall (0.69) far above precision (0.40). The model often does produce the right words, and then keeps producing more.

Cause 2 · word meanings start from nothing

Both embedding tables start as random numbers, and the model gets three passes over the data to learn what 9,215 words mean and how to summarize with them.

Cause 3 · names become <UNK>

Titles are dense with names, and names are often rare across articles, so many title words fall below the 1% threshold. The model is trained to output <UNK> in their place. Because the references go through the same vocabulary, a predicted "unk" can match a reference "unk". That match earns ROUGE credit without the model having produced the actual name.

Cause 4 · the fixed-size bottleneck

Everything about an article of hundreds of words must fit into the 600 numbers of \(\mathbf{c}\) (page 2, section 11). The decoder can't look back at specific article words, so it can't copy a specific detail it failed to store.
