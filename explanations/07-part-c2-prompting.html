1. Instruction tuning

Part C1 fine-tuned T5 on one task. Instruction tuning fine-tunes a pretrained model on a very large collection of tasks, each written as a plain-language instruction followed by its input, with the answer as the target. Examples: "Translate to German: …", "Is this review positive or negative? …", "Summarize: …". Flan-T5 was produced this way from T5 checkpoints, using roughly 1,800 tasks.

Mechanically nothing is new. It's the same encoder–decoder and the same cross-entropy loss (page 2, section 6), with teacher forcing. What changes is the data. Because the instruction is part of the input and varies across so many tasks, the model learns the general skill of reading an instruction and doing what it says. That skill carries over to instructions it never saw during training, which is exactly what the spec relies on.

2. Three ways to use a model: fine-tuning, zero-shot, few-shot

Write \(\theta\) for the model's parameters. The three approaches differ only in whether \(\theta\) changes and in what goes into the input:

\[ \begin{aligned} \textbf{fine-tuning (C1): } & \theta \leftarrow \theta - \eta\nabla_\theta \mathcal{L} \text{ on article–title pairs; input} = \text{article} \\ \textbf{zero-shot (C2): } & \theta \text{ unchanged; input} = \text{instruction} \oplus \text{article} \\ \textbf{few-shot: } & \theta \text{ unchanged; input} = \text{instruction} \oplus (a_1, t_1) \oplus \cdots \oplus (a_k, t_k) \oplus \text{article} \end{aligned} \]

\(\oplus\) means joining text end to end, and \((a_i, t_i)\) is a worked example article with its correct title. In both prompting settings the title is generated as \(\hat{\mathbf{y}} \approx \arg\max_{\mathbf{y}} P_\theta(\mathbf{y} \mid \text{input})\), approximated by beam search. The model learns nothing permanent. Few-shot examples only influence the one generation they appear in.

This project tests zero-shot only. Every C2 input is one instruction followed by one article, with no examples. Few-shot would also have been awkward here. Flan-T5 reads at most 512 tokens, so any worked examples would consume space otherwise used for the article being titled.

3. The prompts and generation settings

Prompt 1"Summarize the following text into a title: {text}"
Prompt 2"Generate a headline for this article: {text}"

For each of the 2 models × 2 prompts × 100 test articles, the notebook:

  1. Fills the article text into the prompt, with the instruction first.
  2. Tokenizes and truncates to 512 tokens. Truncation removes text from the end, so the instruction always survives and the article's opening is kept.
  3. Calls model.generate(max_length=50, num_beams=5, early_stopping=True), the same beam search as C1 (true log-probabilities, length normalization) with a 50-token cap.
  4. Decodes the output pieces back into text.
In the notebook · run on the CPU

Neither the Flan-T5 models nor their inputs are moved to the GPU (there's no .to("cuda"), unlike C1), so all 400 generations ran on the CPU: 1,521.96 s in total, about 3.8 s per title averaged across both model sizes. That's a property of this notebook, not of the models.

4. How C2 is scored

In the notebook · a different ROUGE wrapper

C2 uses HuggingFace's rouge metric, a wrapper around the same rouge_score library as Parts B and C1. By default it does not apply the Porter stemmer, and it combines the per-article F-measures into one aggregate (effectively their mean). It also reports ROUGE-Lsum, a variant intended for multi-sentence summaries. For one-line titles it measures essentially the same thing, and the tables here use ROUGE-L.

Which direction does the stemmer difference push? Stemming maps different surface forms, like "reefs" and "reef", to the same stem. Words that were already identical stay identical, so stemming can only turn non-matches into matches, never the reverse. Match counts, LCS lengths, precision and recall can therefore only stay the same or rise:

\[ \text{ROUGE}_{\text{stemmed}} \;\ge\; \text{ROUGE}_{\text{unstemmed}} \]

So the C2 scores below, computed without stemming, are no higher than they would be under C1's settings. If anything they understate Flan-T5 relative to C1.

Effect of prompt wording

Two ways to state a change from an old score \(a\) to a new score \(b\). Relative change divides by the starting point. Absolute change is the plain difference in score units, which is not the same as a percentage:

\[ \text{relative} = \frac{b - a}{a}, \qquad \text{absolute} = b - a \] \[ \text{Flan-T5-large, prompt 1} \to 2: \quad \text{ROUGE-1 } \frac{0.8728 - 0.8221}{0.8221} = +6.2\%, \quad \text{ROUGE-L } \frac{0.8745 - 0.8207}{0.8207} = +6.6\%, \quad \text{ROUGE-2 } +1.1\% \] \[ \text{Flan-T5-base, prompt 1} \to 2: \quad \text{ROUGE-1 } \frac{0.6325 - 0.6783}{0.6783} = -6.8\% \]

The absolute ROUGE-1 change for the large model is \(+0.051\). By B1's averaging rule, one article going from \(F = 0\) to \(F = 1\) moves the mean by 0.01, so this is roughly five articles' worth of improvement on a 100-article test set. It's a real difference in these results, but a small-sample one.

The same rewording helps the large model and hurts the base model. How much a prompt matters, and in which direction, isn't a fixed property of instruction-tuned models. It interacts with model size.

Effect of model size

\[ \text{base} \to \text{large, ROUGE-1:} \quad \text{prompt 1: } \frac{0.8221 - 0.6783}{0.6783} = +21\%, \qquad \text{prompt 2: } \frac{0.8728 - 0.6325}{0.6325} = +38\% \]

An absolute gain of 0.14 to 0.24, fourteen to twenty-four articles' worth, is the largest and most dependable effect in Part C2.

The gap is \(0.0119\), a little over one article's worth. Given one test set of 100 articles, one training run and one choice of prompt, the fair reading is that the two are effectively tied. And by section 4, if anything, the scoring difference works against Flan-T5.

Why a model never trained on this data can do this well:

  • Scale. Flan-T5-large has about 13 times T5-small's parameters. Flan-T5-base, with the same instruction tuning at a third of the large model's size, lands far lower (0.63–0.68).
  • Relevant instruction tuning. Its instruction collection includes many summarization-style tasks, so "summarize into a title" is close to things it has practised.
  • The task is largely extractive. As noted in C1, a Wikipedia article's first sentence usually names its subject in the title's own words. A capable reader that finds and copies that phrase scores highly without any task-specific training.
